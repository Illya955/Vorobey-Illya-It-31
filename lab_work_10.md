Завдання 1. HAVING на COUNT
Для групування продажів за автомобілем використано зовнішній ключ car_id. За допомогою HAVING залишено тільки ті групи, де кількість продажів перевищує 1.

SELECT car_id, COUNT(*) AS sales_count
FROM sales
GROUP BY car_id
HAVING COUNT(*) > 1;
Результат:

car_id	sales_count
1	2
3	2
4	2
5	2
Межею обрано > 1, тому що це дозволяє знайти автомобілі, які продавалися повторно. Автомобілі з одним продажем відсіюються, а автомобілі з двома або більше продажами залишаються.

Завдання 2. HAVING на іншій агрегатній функції
У цьому завданні використано агрегатну функцію AVG. Потрібно знайти автомобілі, середня ціна продажу яких перевищує 700000.

SELECT car_id,
       AVG(sale_price) AS average_sale_price
FROM sales
GROUP BY car_id
HAVING AVG(sale_price) > 700000;
Результат:

car_id	averagesaleprice
1	720000
3	780000
5	950000
Умова HAVING AVG(sale_price) > 700000 фільтрує вже сформовані групи за середнім значенням ціни продажу.

Завдання 3. WHERE + GROUP BY + HAVING
SELECT car_id,
       COUNT(*) AS sales_count,
       AVG(sale_price) AS average_sale_price
FROM sales
WHERE sale_price >= 600000
GROUP BY car_id
HAVING COUNT(*) >= 2;
У цьому запиті WHERE sale_price >= 600000 фільтрує окремі рядки таблиці sales ще до групування. Продажі з ціною менше 600000 не потрапляють до подальшого групування.

Після цього GROUP BY car_id формує окрему групу для кожного автомобіля.

HAVING COUNT(*) >= 2 уже фільтрує готові групи. Він залишає тільки ті автомобілі, для яких після застосування WHERE залишилося щонайменше два продажі.

Отже, WHERE відсіює окремі рядки до групування, а HAVING відсіює готові групи після групування.

Завдання 4. Свідома помилка WHERE з агрегатом
Для цього завдання навмисно використано агрегатну функцію COUNT(*) у WHERE:

SELECT car_id, COUNT(*) AS sales_count
FROM sales
WHERE COUNT(*) > 1
GROUP BY car_id;
SQLite повертає помилку:

misuse of aggregate: COUNT()
Причина полягає в порядку виконання запиту:

FROM → WHERE → GROUP BY → HAVING → SELECT
WHERE виконується до GROUP BY, тому на цьому етапі групи ще не сформовані й агрегатне значення COUNT(*) для групи ще не існує.

Для фільтрації груп за агрегатним значенням потрібно використовувати HAVING:

GROUP BY car_id
HAVING COUNT(*) > 1;
Завдання 5. LEFT JOIN + GROUP BY + HAVING для «порожніх» груп
SELECT cars.id,
       cars.brand,
       cars.model,
       COUNT(sales.id) AS sales_count
FROM cars
LEFT JOIN sales ON sales.car_id = cars.id
GROUP BY cars.id
HAVING COUNT(sales.id) < 2
ORDER BY cars.id;
Результат:

id	brand	model	sales_count
2	Volkswagen	Golf	1
6	Ford	Focus	1
У цьому запиті використано LEFT JOIN, тому що потрібно зберегти всі автомобілі з таблиці cars, навіть якщо для них немає жодного продажу.

Якщо автомобіль не має пов'язаних записів у sales, LEFT JOIN все одно залишить його в результаті, а COUNT(sales.id) дорівнюватиме 0. Тому умова HAVING COUNT(sales.id) < 2 зможе знайти і автомобілі без продажів.

Якби замість LEFT JOIN використати INNER JOIN, автомобілі без жодного продажу були б видалені ще до GROUP BY. Тому HAVING уже не зміг би побачити їх як групи з COUNT = 0.

У поточних даних усі шість автомобілів мають хоча б один продаж, тому результат містить автомобілі id = 2 та id = 6, які мають по одному продажу.

Контрольні питання
1. Чому не можна просто перенести умову COUNT(*) > 1 після GROUP BY, залишивши WHERE?
Це не спрацює, тому що WHERE призначений для фільтрації окремих рядків і виконується до GROUP BY. Для фільтрації вже сформованих груп за агрегатним значенням потрібно використовувати HAVING.

Правильно:

GROUP BY car_id
HAVING COUNT(*) > 1;
2. Що зміниться в результаті Завдання 5, якщо LEFT JOIN замінити на INNER JOIN?
При використанні INNER JOIN автомобілі, для яких немає жодного продажу, будуть видалені ще до групування.

Тому HAVING COUNT(sales.id) < 2 не зможе повернути автомобілі з нульовою кількістю продажів.

LEFT JOIN необхідний саме для збереження таких «порожніх» груп.

У поточних даних усі автомобілі мають хоча б один продаж, тому саме зараз результат для автомобілів із одним продажем не зміниться.

3. Як одночасно прибрати непотрібні рядки та показати групи із сумою більше певного порогу?
Потрібно використати WHERE для фільтрації окремих рядків, а HAVING — для фільтрації готових груп.

Порядок запису:

SELECT ...
FROM ...
WHERE ...
GROUP BY ...
HAVING ...
Наприклад:

SELECT car_id,
       SUM(sale_price) AS total_sales
FROM sales
WHERE status <> 'скасовано'
GROUP BY car_id
HAVING SUM(sale_price) > 1000000;
WHERE прибирає скасовані продажі до групування, а HAVING залишає тільки групи, у яких сума продажів перевищує 1000000.

Поставити HAVING перед GROUP BY не можна.

Логічний порядок виконання запиту:

FROM → WHERE → GROUP BY → HAVING → SELECT
При цьому порядок написання SQL відрізняється від порядку виконання: SELECT записується на початку запиту, але логічно виконується після FROM, WHERE, GROUP BY та HAVING.
