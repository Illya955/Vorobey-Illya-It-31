Практична робота №12
Сортування і фільтрація даних

Варіант №5 — Автосалон

Завдання 1. ORDER BY за однією колонкою

Для сортування продажів використано команду ORDER BY sale_price DESC.

Вона впорядковує записи за ціною продажу від найбільшої до найменшої.

Першим у результаті опинився продаж №5 автомобіля №5 від 10.08.2026 на суму 950 000 грн, оскільки це найбільша ціна серед усіх десяти продажів.

Завдання 2. ORDER BY за кількома колонками

Використано сортування за двома колонками: status та price.

Спочатку автомобілі впорядковуються за статусом у порядку зростання (ASC). Потім автомобілі з однаковим статусом сортуються за ціною від найбільшої до найменшої (DESC).

Друга колонка потрібна для додаткового впорядкування записів усередині однакової групи статусів.

Наприклад, серед автомобілів зі статусом «в наявності» першою буде Skoda Octavia за 780 000 грн.

Завдання 3. Топ-3 через ORDER BY і LIMIT

Для отримання трьох найдорожчих продажів використано команди ORDER BY sale_price DESC та LIMIT 3.

Результат:

Продаж №5 — 950 000 грн.
Продаж №10 — 940 000 грн.
Продаж №3 — 780 000 грн.

Спочатку SQL сортує всі продажі за спаданням ціни, а потім залишає лише перші три записи.

Якщо прибрати ORDER BY, команда LIMIT 3 поверне три записи без гарантії, що вони будуть найдорожчими.

Саме тому порядок команд має значення.

Завдання 4. DISTINCT і BETWEEN

Частина А. DISTINCT

За допомогою SELECT DISTINCT status FROM cars отримано список унікальних статусів автомобілів.

У результаті отримано три унікальні значення:

в наявності;
продано;
зарезервовано.

Кількість унікальних значень: 3.

Частина Б. BETWEEN

Для пошуку автомобілів, випущених із 2020 до 2023 року включно, використано BETWEEN 2020 AND 2023.

За результатом запиту знайдено 5 автомобілів.

Команда BETWEEN доречна, оскільки потрібно знайти записи в числовому діапазоні.

IN краще використовувати, коли необхідно перевірити належність значення до конкретного списку, наприклад декількох окремих років.

Завдання 5. LIKE і регістр кирилиці

Для перевірки регістрозалежності використано два запити:

LIKE 'в%';
LIKE 'В%'.

Результати експерименту:

маленька літера «в» — 3 записи;
велика літера «В» — 0 записів.

У SQLite оператор LIKE за замовчуванням не розрізняє регістр для латинських символів ASCII, але кириличні символи обробляються з урахуванням регістру.

Це важливо для курсу, оскільки більшість текстових значень у базі українською мовою. Під час пошуку необхідно враховувати правильний регістр літер.

Контрольні питання

1. Чому ORDER BY потрібно писати перед LIMIT?

ORDER BY спочатку впорядковує всі записи за заданим критерієм. LIMIT після цього обмежує кількість результатів. Без ORDER BY немає гарантії, що будуть отримані саме потрібні записи.

2. Коли використовувати IN, а коли BETWEEN?

IN використовується для перевірки належності значення до конкретного списку. BETWEEN використовується для перевірки належності значення до певного діапазону. Наприклад, IN підходить для окремих значень, а BETWEEN — для діапазону років випуску.

3. Чому важливо враховувати регістр кирилиці?

Тому що SQLite за замовчуванням обробляє кириличні символи в LIKE з урахуванням регістру. Через це пошукові запити з великою та маленькою літерами можуть повертати різну кількість результатів.
