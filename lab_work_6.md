Завдання 2
У таблиці cars було оновлено ціну автомобіля з id = 1.

UPDATE cars
SET price = 730000
WHERE id = 1;

Використання UPDATE є доречним, оскільки автомобіль залишається тим самим об'єктом, а змінюється лише його властивість — ціна. Тому немає потреби видаляти старий запис і створювати новий.

Завдання 4
У таблиці sales для зовнішнього ключа customer_id використовується:

FOREIGN KEY (customer_id)
REFERENCES customers(id)
ON DELETE SET NULL

Було виконано:

DELETE FROM customers
WHERE id = 1;

Перед видаленням покупця з id = 1 у таблиці sales були записи з id = 1 та id = 8, які посилалися на цього покупця.

Фактичний результат
Після видалення покупця записи sales залишилися в таблиці, але їхнє значення customer_id було змінено на NULL.

Таким чином, фактичний результат відповідає прогнозу: спрацювала дія ON DELETE SET NULL.

Кількість записів у таблиці sales при цьому не зменшилася, оскільки SET NULL не видаляє пов'язані записи, а лише змінює значення зовнішнього ключа.

Перевірка ON DELETE RESTRICT
Для зовнішнього ключа car_id використовується:

FOREIGN KEY (car_id)
REFERENCES cars(id)
ON DELETE RESTRICT

Автомобіль з id = 1 використовується в таблиці sales, тому було виконано спробу:

DELETE FROM cars
WHERE id = 1;

SQLite повернув помилку:

FOREIGN KEY constraint failed

Це означає, що ON DELETE RESTRICT спрацював правильно. Автомобіль не був видалений, оскільки на нього існують посилання з таблиці sales.

Контрольні питання
1.При SET колонка = колонка + 1 нове значення залежить від поточного значення колонки. Наприклад, якщо ціна була 720000, після SET price = price + 10000 вона стане 730000.При SET колонка = 730000 значення безпосередньо встановлюється рівним 730000, незалежно від попереднього значення.

2.NOT NULL, UNIQUE і CHECK є обмеженнями цілісності таблиці, тому SQLite перевіряє їх під час зміни даних через UPDATE.Перевірка зовнішніх ключів у SQLite керується окремо. Для її виконання потрібно увімкнути:PRAGMA foreign_keys = ON;
У цій практичній роботі ця команда була виконана на початку.

3.При ON DELETE CASCADE після видалення автомобіля з таблиці cars автоматично видалилися б усі пов'язані записи з таблиці sales. При ON DELETE RESTRICT, який використовується в цій роботі, видалення автомобіля блокується, якщо на нього посилається хоча б один запис sales.

4.DELETE без WHERE видаляє всі записи таблиці. Наприклад:DELETE FROM sales; видалить усі продажі.Така команда може виконатися без помилки та призвести до втрати всіх записів. Тому для видалення одного конкретного рядка потрібно використовувати WHERE, бажано з первинним ключем: 
DELETE FROM sales 
WHERE id = 11;
