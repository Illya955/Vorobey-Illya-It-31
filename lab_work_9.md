Завдання 4.

Для цього завдання використано дві колонки: статус автомобіля та місяць продажу.

SELECT cars.status,
       strftime('%Y-%m', sales.sale_date) AS sale_month,
       COUNT(*) AS sales_count
FROM sales
JOIN cars ON cars.id = sales.car_id
GROUP BY cars.status, sale_month
ORDER BY cars.status, sale_month;


Результат:

status	sale_month	sales_count
в наявності	2026-08	5
зарезервовано	2026-08	2
продано	2026-08	3

Завдання 5.

Для демонстрації особливості SQLite виконано такий запит:

SELECT car_id, sale_price, COUNT(*) AS sales_count
FROM sales
GROUP BY car_id;


У цьому запиті car_id входить до GROUP BY, а COUNT(*) є агрегатною функцією. Проте sale_price не входить до GROUP BY і не використовується в агрегатній функції.

SQLite дозволяє виконати такий запит без помилки.

Наприклад, для автомобіля з car_id = 1 у таблиці sales є два значення ціни:

720000;

Однак після групування за car_id у результаті буде показано лише одне значення sale_price.

SQLite бере значення з одного з рядків, що належать відповідній групі. Сам запит не визначає, який саме рядок потрібно вибрати.

Тому на це значення не можна покладатися. Воно може залишатися однаковим під час повторних запусків, але SQL не гарантує, що воно завжди буде саме таким. Зміна даних, індексів або плану виконання запиту може вплинути на результат.

Якщо потрібно отримати конкретну характеристику ціни, потрібно використати агрегатну функцію, наприклад:

AVG(sale_price)


для середньої ціни,

MIN(sale_price)


для мінімальної ціни або

MAX(sale_price)


для максимальної ціни.

Контрольні питання
1. Чому у Завданні 2 потрібно групувати за id таблиці-виміру, а не за текстовою колонкою?

Первинний ключ id однозначно визначає конкретний запис таблиці cars. Тому групування за cars.id дозволяє сформувати окрему групу для кожного автомобіля.

Текстові колонки, наприклад brand або model, можуть повторюватися. Якщо групувати за текстовою колонкою, різні записи можуть потрапити до однієї групи.

2. Що станеться, якщо у Завданні 2 замінити LEFT JOIN на INNER JOIN?

LEFT JOIN залишає всі автомобілі з таблиці cars, навіть якщо для них немає продажів. У такому випадку для автомобіля без продажів COUNT(sales.id) покаже 0.

INNER JOIN залишить тільки ті автомобілі, для яких існує хоча б один відповідний запис у таблиці sales.

У поточних даних усі шість автомобілів мають хоча б один продаж, тому зараз заміна LEFT JOIN на INNER JOIN не змінить кількість рядків.

3. Звідки SQLite взяв значення у зайвій колонці та що зробив би PostgreSQL?

SQLite дозволяє виконувати запити, у яких неагрегована колонка присутня в SELECT, але не входить до GROUP BY.

Для sale_price SQLite повертає значення з одного з рядків відповідної групи. Оскільки в групі може бути кілька різних значень sale_price, конкретне значення не можна вважати гарантованим.
