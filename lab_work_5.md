Для перевірки було виконано вставку нового продажу без зазначення поля sale_date:

INSERT INTO sales (car_id, customer_id, sale_price)
VALUES (1, 1, 710000);

Після цього виконано SELECT:

SELECT id, car_id, customer_id, sale_date, sale_price
FROM sales
WHERE id = (SELECT MAX(id) FROM sales);

Отримано:

id = 11
car_id = 1
customer_id = 1
sale_date = 2026-09-22
sale_price = 710000.0

Отже, SQLite автоматично підставив поточну дату 2026-09-22.

Завдання 5.
Для перевірки було використано обмеження NOT NULL для стовпця customers.city.

Виконано:

UPDATE customers
SET city = NULL
WHERE id = 1;

SQLite повернув помилку:

NOT NULL constraint failed: customers.city

Це підтверджує, що обмеження однаково діє як при вставці нового рядка через INSERT, так і при оновленні вже існуючого рядка через UPDATE.

Завдання 6.
NOT NULL
Обмеження NOT NULL для customers.city потрібне тому, що для кожного клієнта в базі даних повинно бути обов'язково зазначене місто.

UNIQUE
Обмеження UNIQUE для customers.phone потрібне тому, що один номер телефону не повинен бути одночасно прив'язаний до кількох різних клієнтів.

CHECK
Обмеження CHECK (price > 0) для cars.price потрібне тому, що ціна автомобіля за змістом даних повинна бути додатною.

DEFAULT
Обмеження DEFAULT (date('now')) для sales.sale_date потрібне тому, що при відсутності явно заданої дати продажу доцільно автоматично записувати поточну дату.

Контрольні питання
1.SQLite має обмежену реалізацію ALTER TABLE і не підтримує додавання довільного обмеження CHECK до вже існуючої таблиці через ALTER TABLE ... ADD CONSTRAINT.

Тому таблицю потрібно перестворити: перейменувати стару таблицю, створити нову з потрібним обмеженням, перенести дані через INSERT ... SELECT і видалити стару таблицю.

2.Під час перенесення даних до нової таблиці команда INSERT ... SELECT спробує записати NULL у стовпець, який має NOT NULL, тому перенесення завершиться помилкою NOT NULL constraint failed.

3.Функціонально вони не відрізняються: після перестворення таблиці доданий CHECK діє так само, як і обмеження, оголошене під час початкового CREATE TABLE.

4.DEFAULT не забороняє певне значення, а автоматично підставляє значення, коли користувач не задає його під час INSERT.
Тому DEFAULT перевіряють вставкою нового рядка без зазначення відповідного стовпця та подальшим SELECT, який показує автоматично підставлене значення.
